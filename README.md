# 📚 Obsidian Vault

Bienvenue dans ce vault 👋

Ce dépôt est un **condensé évolutif de notes sur le développement**, conçu comme une base de connaissances communautaire, structurée et maintenable dans le temps.

Il rassemble des fiches sur différents domaines du développement et de l’informatique : langages, outils, algorithmique, mathématiques, concepts fondamentaux, pièges classiques et bonnes pratiques.

L’objectif est de construire une ressource utile, lisible et durable, que chacun puisse consulter, enrichir et améliorer.

## 🎯 Objectif

Ce projet vise à :

- centraliser des notes techniques synthétiques ;
- organiser les connaissances par domaine et par module ;
- proposer des fiches faciles à relire et à maintenir ;
- fournir une base commune de contribution ;
- faire émerger, progressivement, une ressource communautaire de qualité.

Le dépôt n’a pas vocation à être exhaustif. Il cherche avant tout à être **clair, cohérent et utile**.

## 🗂️ Organisation du vault

Le contenu est structuré par **domaine**, puis par **module** lorsque cela est pertinent.

Chaque module peut contenir :

- un **index des fiches** ;
- un **glossaire** ;
- une page de **pièges classiques** ;
- plusieurs **fiches numérotées**.

Exemple d’arborescence :

```text
[domaine]/
└── [module]/
    ├── [Module] — Index des fiches.md
    ├── [Module] — Glossaire.md
    ├── [Module] — Pièges classiques.md
    ├── [Module] 01 — [Titre].md
    ├── [Module] 02 — [Titre].md
    └── ...
```

Le point d’entrée principal du contenu est `Home.md`.

## ✍️ Principes éditoriaux

Les fiches du vault doivent rester :

- **synthétiques** ;
- **structurées** ;
- **pédagogiques** ;
- **faciles à parcourir** ;
- **cohérentes entre elles**.

Selon le sujet, une fiche peut être orientée :

- **code** ;
- **théorie** ;
- **glossaire** ;
- **retour d’expérience / pièges classiques**.

## 🤝 Contributions

Les contributions sont les bienvenues.

Tu peux proposer :

- l’ajout d’une nouvelle fiche ;
- la correction d’une fiche existante ;
- une amélioration de formulation ;
- un exemple plus pertinent ;
- un enrichissement de glossaire ;
- une clarification sur un concept ou un piège fréquent.

Chaque contribution, même modeste, peut améliorer la qualité globale du vault.

## 📏 Règle de contribution

Pour préserver l’homogénéité du dépôt, **toute proposition d’ajout ou de modification de fiche doit respecter le format défini dans le template situé à la racine du repository** :

- `_template_categorie.md`

Ce template définit notamment :

- l’arborescence attendue ;
- la structure des index ;
- le format des fiches numérotées ;
- les conventions de nommage ;
- les tags ;
- les callouts ;
- les règles d’écriture des exemples de code.

Avant toute contribution, merci de consulter ce fichier et de t’y conformer.

## 🧩 Conventions générales

Le vault suit plusieurs conventions simples :

- séparateur de nommage : ` — `
- numérotation sur deux chiffres : `01`, `02`, `03`, etc.
- fichiers spéciaux sans numéro :
  - `Module — Index des fiches`
  - `Module — Glossaire`
  - `Module — Pièges classiques`
- tags sur la première ligne, sans frontmatter YAML
- langage toujours précisé dans les blocs de code
- exemples volontairement courts, ciblés et utiles

## 👥 Public visé

- aux contributeurs souhaitant participer à une ressource technique communautaire.

## 💻 Utilisation

Le contenu peut être consulté directement sur GitHub, mais le vault est principalement pensé pour être utilisé dans **Obsidian**, afin de bénéficier :

- des liens internes entre les fiches ;
- d’une navigation plus fluide ;
- d’une meilleure lecture des index ;
- d’une exploration plus naturelle du contenu.

## 🌱 Évolution du projet

Le vault est destiné à évoluer en continu.

De nouveaux domaines, modules et fiches peuvent être ajoutés au fil du temps, à condition de respecter les conventions communes et la structure définie par le template.
